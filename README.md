# 自己紹介・自己PRの素材

## 強み・アピールポイント

### 1. 既存コードや設計思想を読み解いて実装できる
- 開発アルバイトで、toB向けiOSアプリの新機能実装やiPhone対応を担当した。
- いきなり実装に入るのではなく、既存コードを読み、採用されている設計パターンや責務分離を理解してから実装した。
- TCAを用いた開発や、View構造の再設計を通じて、プロジェクト全体の設計に沿った実装を意識してきた。
- アピール表現:
  - 「既存の設計思想を読み解き、プロダクト全体の一貫性を保ちながら実装できる」
  - 「単に動くものを作るのではなく、保守性やチーム開発での扱いやすさを意識できる」

### 2. iOSクライアント開発を軸にした実務経験がある
- 個人開発と開発アルバイトを合わせて、iOSネイティブ開発に継続的に取り組んできた。
- Swift、SwiftUI、TCA、SPM、GitHub Actionsなどを利用した経験がある。
- iPad向けに設計された画面をiPhone向けに再設計し、画面サイズやデバイス特性に合わせたUI最適化を行った。
- アピール表現:
  - 「iOSクライアント開発を軸に、ユーザー体験と実装品質の両方を意識して開発してきた」
  - 「デバイス特性を踏まえたUI設計・実装に取り組んできた」

### 3. ユーザー体験を意識して改善できる
- iPad向け画面をそのままiPhoneに移植すると操作性が落ちるため、View構造を再設計した。
- Figmaで事前に画面構成を確認し、デザイナーやチームメンバーと認識を合わせてから実装した。
- 個人開発のタイマーアプリでは、家族から画面遷移や動作速度へのフィードバックを受け、ユーザー視点の重要性を学んだ。
- アピール表現:
  - 「機能が動くことだけでなく、実際のユーザーが迷わず使える体験を重視している」
  - 「ユーザーのフィードバックをもとに、UIや操作感を改善できる」

### 4. チームの生産性を高める行動ができる
- PRを適切に分割し、デモ動画や補足コメントを添えることでレビューしやすい状態を作った。
- レビュー依頼前に自分の目やAIを使って事前確認し、軽微な修正を先に解消した。
- メッセージでは冒頭に目的を示し、必要な情報を整理して共有することで、相手の認知負荷を下げることを意識した。
- これらの工夫により、タスク進行を約1か月短縮した経験がある。
- アピール表現:
  - 「自分の実装だけでなく、レビューや情報共有を含めてチーム全体が動きやすい開発を意識している」
  - 「レビュアーの負荷を下げ、意思決定やマージまでの速度を上げる工夫ができる」

### 5. 課題を分解し、粘り強く原因特定できる
- 不具合修正では、発生条件を整理し、関与する関数や処理の流れを一つずつ追って原因コードを特定した。
- 詰まった際には一人で抱え込まず、マネージャーに状況や調査方針を共有して進めた。
- 原因発見後もすぐに修正するのではなく、影響範囲や修正方針を考えた上で対応した。
- アピール表現:
  - 「問題を感覚的に扱わず、発生条件・原因・影響範囲に分解して解決できる」
  - 「不確実な状況でも、周囲と認識を合わせながら着実に前へ進められる」

### 6. 未知の技術にキャッチアップして成果につなげられる
- iOS開発を主軸にしつつ、未経験に近いReact/FastAPIのWeb開発プロジェクトにも参加した。
- ドキュメントや既存コードを読み、利用ライブラリや開発フローを理解してから実装した。
- AIを活用して処理の流れや関連関数を把握し、生成されたコードを自分でレビュー・検証する形で開発を進めた。
- Web開発では、ユーザー操作とサーバー処理を分離する改善により、APIリクエスト削減にも貢献した。
- アピール表現:
  - 「専門外の技術でも、学習方法を組み立てて短期間で実務に適応できる」
  - 「AIを使うだけでなく、出力を検証し、自分の理解を通して品質を担保できる」

### 7. AIを開発効率と品質向上に活用できる
- GitHub CopilotやClaude Codeなどを使い、コードレビュー、デバッグ、実装方針の整理に活用してきた。
- PR前の事前レビューで軽微なミスを減らし、レビュアーが本質的な設計や仕様の確認に集中できるようにした。
- AIの出力を盲信せず、既存設計との整合性やモジュール間の関係を自分で確認した。
- アピール表現:
  - 「AIを開発速度の向上だけでなく、レビュー品質や理解の補助に活用できる」
  - 「AIの出力を検証し、プロダクトの品質に責任を持つ姿勢がある」

### 8. 個人開発で課題発見からリリースまで経験している
- 作業時間を測定・記録し、生産性を可視化するiOSアプリをApp Storeで公開した。
- タイマー終了時に自動で記録する仕組みにより、手動入力の手間を減らした。
- Chartsによる可視化やカレンダー連携など、ユーザーの作業管理を支援する機能を実装した。

## その他

### iPad向けアプリのiPhone対応
- 課題: iPad向けの画面構成をそのままiPhoneに移植すると、操作性や情報設計が悪くなる。
- 行動: 既存コードと設計思想を読み、Figmaで画面構成を確認しながらView構造を再設計した。
- 成果: iPhoneでも自然に使えるUIに落とし込み、プロダクトの利用可能な環境を広げた。
- 学び: 動くものを作るだけでなく、デバイス特性やプロダクト全体の一貫性を守る視点が重要。

### レビュー負荷削減とタスク短縮
- 課題: PRの差分が大きいと、レビューやマージまでに時間がかかる。
- 行動: PRを分割し、デモ動画や補足コメントを添え、レビュー前にAIと自分の目で事前確認した。
- 成果: レビューしやすい状態を作り、タスク進行を約1か月短縮した。
- 学び: エンジニアの価値は個人の実装速度だけでなく、チーム全体の生産性を上げる行動にもある。

### 不具合修正
- 課題: UI上の不具合の原因特定に時間がかかった。
- 行動: 発生条件を整理し、マネージャーに状況を共有しながら、関係する関数を一つずつ追って原因を特定した。
- 成果: 原因コードを見つけ、影響範囲を考えた上で修正方針を立てた。
- 学び: 課題を分解し、周囲と連携しながら進める力が実務では重要。

### 未経験Web開発への適応
- 課題: iOS中心の経験から、React/FastAPIのWeb開発プロジェクトに配属された。
- 行動: ドキュメントや既存コードを読み、AIを活用して処理の流れを理解しながら実装した。
- 成果: ユーザー操作とサーバー処理を分離する改善に取り組み、APIリクエスト削減にも貢献した。
- 学び: 未知の領域でも、学習戦略と検証プロセスを持てば実務レベルの成果につなげられる。
