# 採点基準（rubric）

添削モードの採点と、下書きモードの執筆後セルフチェックで共用する。
8項目 × 0〜2点 = 16点満点。**13点以上で提出可**。ただし「自動不合格」に1つでも該当したら点数に関係なく直す。
加えて、書類選考を通過しやすいかを「選考通過の観点」S1〜S6 で判定する（下の節）。提出可の条件は「自動不合格なし・13点以上・0点の項目なし・S1〜S6 がすべて ○」。

なぜこの8項目か: ES は「面接で深掘りされる前提の文章」なので、読み手（採用担当）が 30 秒で「何をした人か」「再現性があるか」「なぜうちか」を判断できることが全て。抽象語・主観成果・字数超過は、その判断を妨げる典型的な原因。

## 自動不合格（点数に関係なく修正）

| 条件 | 確認方法 |
|---|---|
| 上限文字数の超過 | `count_chars.py --limit N` が OVER |
| 事実の捏造（正典表・過去回答・ユーザー発言に無い数値や出来事） | `material-index.md` の正典表と照合。新規事実は「確認事項」へ退避 |
| 設問に答えていない（例: キャッチコピーを求められてエピソードだけ書く） | 設問原文を読み直し、冒頭1文が問いに直接答えているか |
| 時制の誤り（終了済みインターンを現在形で書く、「インターンでは」を本選考で使う） | `material-index.md` の時系列表 |

## 8項目

### 1. 設問への直接回答・結論ファースト
- **2点**: 冒頭1文で設問に直接答えている（「私の強みは〜です」「〜に挑戦したいです」「志望理由は〜です」）。設問が複数の問いを含む場合（背景・行動・変化など）、全部に答えている。
- **1点**: 答えてはいるが、冒頭が背景説明で結論が2段落目以降にある。
- **0点**: 設問と回答がずれている。例: WealthNavi「キャッチコピー」に対し、コピー本体が無くエピソードだけ書いた過去回答。
- 機械チェック: 不可（設問原文と突き合わせて判断）。

### 2. 具体性
- **2点**: 場面（どのプロダクト・どのチーム規模）、自分の役割、使った技術・道具の固有名詞（TCA、Figma、React/FastAPI、GitHub Actions など）、判断の理由が書かれている。
- **1点**: 固有名詞はあるが「なぜそうしたか」が無い。
- **0点**: 「様々な」「多くの」「積極的に」など抽象語だけで場面が浮かばない。例: Sansan「キャリアビジョン」。
- 機械チェック: 一部可（固有名詞の有無を grep）。

### 3. 数値・検証可能な成果
- **2点**: `material-index.md` の正典表にある数値が1つ以上、成果として書かれている（志望動機系は、経験を語る箇所に1つあれば足りる）。
- **1点**: 数値は無いが、第三者が確認できる客観的成果がある（App Store 公開、両デバイスで利用可能になった、など）。
- **0点**: 「大幅に」「飛躍的に」「成長できた」など主観のみ。
- 機械チェック: 可。`python3 -c` などで正規表現 `\d+\s*[〜~]?\s*\d*\s*(%|％|か月|ヶ月|名|年|倍)` を当てる。
- 注意: 数値の捏造は自動不合格。無いなら1点で止めて、確認事項として「書ける数値はありますか」と聞く。

### 4. 構成
- **2点**: エピソード系は 課題 → 行動 → 成果 → 学び の4要素が判別できる。志望動機系は 原体験・価値観 → 企業との接点 → 入社後の貢献 の3要素が判別できる。要素の順序が読みやすい。
- **1点**: 要素が3つ（学びが無い、課題が曖昧など）。
- **0点**: 行動の羅列だけ、または感想だけ。例: GREE「研究内容」（成果・学びが無い）。
- 機械チェック: 不可。

### 5. 企業との接点（志望動機・挑戦したいこと・キャリアビジョン系のみ。他は N/A として満点扱い）
- **2点**: 企業固有の固有名詞（プロダクト名、ミッションの言い換え、技術ブログで見た取り組み、職種の要件）が2つ以上あり、それぞれが自分の経験・価値観と1対1で結ばれている（「MIXI が〜しているのは、私が〜で学んだ〜と重なる」の形）。
- **1点**: 固有名詞はあるが会社説明の書き写しになっている、または1つだけ。
- **0点**: 「多様な事業」「成長できる環境」など、どの会社にも当てはまる理由だけ。例: リクルート「志望動機」。
- 機械チェック: 一部可（企業固有名詞の grep。結び方は判断）。

### 6. 一貫性
- **2点**: 同じ企業の他設問や `self_introduce.md` と矛盾しない。時制が今日基準で正しい。同一企業内で同じエピソードを2回使っていない（`es_index.py --episodes --company 企業名` で確認）。他社で使い倒したエピソードを、その企業で初めて使うぶんは問題ない。
- **1点**: 軽い重複（同じ数値を同じ企業の2設問で使う等）。
- **0点**: 他で一度も出てこないエピソード（面接で説明できない）、終了したインターンが現在形、「インターンでは〜したい」が本選考に残っている。例: リクルート志望動機の「ドキュメント自動生成スクリプト」は他のどこにも出てこない。
- 機械チェック: 一部可（`インターンでは|インターンを志望|現在.{0,10}従事しています` を grep、`es_index.py --episodes`）。

### 7. 文字数
- **2点**: 許容帯内（「以内」90〜100% / 「約・程度」90〜110% / 「以上」100〜120%）。
- **1点**: 下限を少し割る（以内で 80〜89%）。
- **0点**: 上限超過（→ 自動不合格）、または 80% 未満。例: GREE 研究 71%。
- 機械チェック: 可。`count_chars.py --limit N --mode within|about|atleast`。

### 8. 文体・冗長
- **2点**: 以下すべてを満たす。
  - 一文 100 字超が 0 個
  - 口癖が各 1 回以内: 「単なる／単に」「だけでなく」「と考えています」「設計思想」「認知負荷」
  - 誇張副詞なし: 飛躍的、劇的、徹底的、大幅に、極めて、非常に
  - 「貴社」1 回以内
  - 主観成果（頑張った、成長できた、痛感した）に根拠が添えてある
  - です・ます調で統一（箇条書き内の体言止めは可）
- **1点**: 上のうち1〜2項目に違反。
- **0点**: 3項目以上違反。
- 機械チェック: 可（各語を grep して回数を数える。一文の長さは「。」で split）。

## 選考通過の観点（S1〜S6）

8項目は「文章として正しいか」の基準。こちらは「書類選考で通すと判断されるか」の基準で、執筆時にも意識し、レビュー（`review.md` 段階 O）では ○ / ✕ で判定する。**1つでも ✕ なら FAIL**。
採用担当は1通を短時間で読み、「会ってみたいか（面接に呼ぶか）」を決める。点数が高くても、読後に印象が残らない ES は通らない。

| # | 観点 | ○ の条件 | ✕ の典型 |
|---|---|---|---|
| S1 | 冒頭で掴む | 冒頭2文だけ読んで「何ができる人か／何をしたい人か」と評価ポイントが分かる | 背景説明から始まり、強みや結論が後半に出る |
| S2 | 求める人物像との一致 | 企業の求める人物像・バリュー・職種要件の1つ以上に、回答の強みが明確に対応している（リサーチメモに根拠がある）。リサーチ不要な設問では、エンジニア職で評価される行動特性（自走力、チームへの波及、ユーザー視点、学習の速さ）のどれかに対応している | 強みは書いてあるが、その会社・職種で活きる理由が読み取れない |
| S3 | 差別化 | この人の判断・工夫・固有の経験が文中にあり、同じ大学・同じ技術の別の学生では書けない | 「チームで協力して」「ユーザー目線で」など、誰でも書ける一般論で段落が終わる |
| S4 | 再現性・入社後への接続 | 成果が偶然でなく、本人の考え方・やり方から生まれたと分かり、それが入社後にも発揮されるイメージが持てる | 成果だけで「なぜできたか」が無い、または入社後と結びつかない |
| S5 | 面接につながるフック | 面接で「ここを詳しく聞きたい」と思わせる具体（判断の分岐、数値の裏側、工夫の中身）が1つ以上あり、本人が説明できる素材の範囲に収まっている | 全部書き切って質問の余地が無い、または素材に無い話で深掘りに耐えない |
| S6 | 減点表現が無い | 受け身・他責・条件面の志望理由・自信の無さが無い | 「学ばせていただきたい」「成長できる環境に惹かれ」「〜してもらった」「〜かもしれません」、前職・インターン先の否定、待遇や働き方だけの志望理由 |

補足:
- S2 で企業の求める人物像を使うときは、`company-research.md` のリサーチメモにある事実だけを根拠にする。推測で人物像を作らない。
- S6 の「成長したい」は、何をどう伸ばし、それで会社に何を返すかまで書けば減点にならない（例:「大規模開発の設計を学び、〜で貢献したい」）。
- 通過観点を満たすために事実を盛らない。盛った ES は面接で落ちる（自動不合格「事実の捏造」が優先）。

## セルフチェックの手順（下書きモード）

1. `count_chars.py --limit N --mode ...` を実行。OVER なら `style-guide.md` の「削る優先順位」で削る。
2. 自動不合格4条件を確認。
3. 8項目を採点し、△（1点以下）を直す。13点未満なら骨子に戻る。
4. 選考通過の観点 S1〜S6 を確認し、✕ を直す。
5. その後 `review.md` の段階 O（出力レビュー）に回す。
6. 報告に「スコア x/16」、1点以下だった項目とその理由、S1〜S6 の結果を書く。
