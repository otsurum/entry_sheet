# 企業リサーチの手順

対象: 志望動機、入社後に挑戦したいこと、キャリアビジョン（その会社での活躍イメージ）、興味を持ったきっかけ、逆質問。
自己PR・ガクチカ・研究内容には不要（時間を使わない）。

目的は「なぜこの会社か」を、その会社にしか当てはまらない事実で書くこと。「多様な事業」「成長できる環境」はどの会社にも当てはまり、読み手は志望度が低いと判断する。

## 手順

1. **既存の記述を先に見る。** `es_index.py --company 企業名` で、その企業について過去に書いた固有名詞（MIXI ならモンスト、pixiv なら「全ての表現を応援する」）を確認する。あれば検索の起点にし、矛盾させない。
2. **WebSearch を 2〜4 回。** クエリの型:
   - `"企業名" 新卒採用 エンジニア`（職種要件・求める人物像）
   - `"企業名" ミッション ビジョン バリュー`
   - `"企業名" テックブログ iOS` または ` モバイル` ` AI` ` テスト`（自分の強みと接点になりそうな話題）
   - `"企業名" プロダクト 一覧` または主要プロダクト名
3. **WebFetch で 2〜3 ページ読む。** 優先順位: 新卒採用ページ → ミッション/バリューページ → 技術ブログの直近1年で iOS・モバイル・AI 活用・テスト・設計に関する記事 → プロダクト紹介 → プレスリリース/IR（事業の方向性）。
4. **メモを作る。** 固有名詞ごとに「事実（1行）」「出典 URL」「自分のどの素材と結べるか」を書く。最終報告にこのメモを載せる（面接前にユーザーが読み直せる）。

## 接点の作り方

「企業の事実」×「自分の経験・価値観」を **1対1で結ぶ文** を最低2つ作る。

- 形: 「（企業）が（固有名詞の事実）に取り組んでいる点は、私が（素材のエピソード）で学んだ（価値観）と重なります」
- 企業の事実だけ並べる（会社説明の書き写し）のも、自分の話だけするのもだめ。片方だけだと「調べたか」「自分に引き寄せたか」のどちらかが伝わらない。
- 結びやすい素材の対応表:

| 企業の特徴 | 結びやすい素材 |
|---|---|
| チーム開発・コラボレーション・グループウェア | PR分割・デモ動画で約1か月短縮、リモートでの情報共有の工夫、対話ロボット研究（コミュニケーションの質） |
| ユーザー体験・toC プロダクト | mecap への家族フィードバック、iPad→iPhone 再設計 |
| 大規模・高トラフィック | 自認する弱み（スケーラビリティ経験不足）を「ここで学びたい」に転換、Swift Testing × TCA |
| AI 活用を推進 | AI メンター活用（React/FastAPI）、PR 前 AI レビュー、実装速度30〜40%向上 |
| モバイルアプリが主力 | iOS 約3年、TCA/SPM 設計、iOSDC・try! Swift 参加と登壇 |
| BtoB・業務効率化 SaaS | 工事現場アプリの API リクエスト60〜70%削減、燈での toB アプリ開発 |
| 上流工程から関わる文化 | kubell インターンでのユーザーストーリー作成、要件定義力を伸ばしたい意欲 |

## 書いてはいけないこと

- ミッション文の丸写し。自分の言葉で言い換える。丸写しは面接官に見抜かれ、かつ他者の著作物の引用になる。引くなら「」で短く1回。
- 検索結果に無い事実。「〜だと聞いています」「〜と伺いました」で推測を事実に見せない。
- ユーザー数・売上などの数値は、出典ページに明記されているときだけ。年次も添える（「2025年時点で〜」）。
- 競合との比較で他社を下げる表現。

## 検索できない・情報が薄いとき

- 採用ページに職種要件が無い小規模企業は、プロダクトと技術スタック（求人票、GitHub、Qiita/Zenn の社員記事）から接点を作る。
- それでも固有名詞が1つしか集まらないときは、無理に埋めず「確認事項」で「説明会・面談で聞いた内容があれば教えてください」とユーザーに聞く。ユーザーが直接聞いた話は、Web に無い最も強い接点になる。
